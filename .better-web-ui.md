# HogarIA design context

## People and jobs

- Audience: Spanish-speaking household members who plan meals and cook at mixed experience levels, including beginners; household managers also configure shared AI providers.
- Core recipe jobs: browse, create and edit recipes; choose beginner/intermediate/expert instructions; adjust servings; cook step by step with clear tips, warnings, timers, nutrition and storage guidance.
- Most sensitive context: mobile use in the kitchen, often one-handed; desktop is used for planning and editing.

## Product feel

- Calm, practical, warm, trustworthy and non-judgmental; Spanish (Spain) copy by default. Prefer calm confidence over marketing language.
- Preserve HogarIA's warm neutral surfaces, orange/green semantic palette, typography, tokens, shared controls and shell. Do not invent a second design system for recipes.
- Keep forms and settings minimal, aligned and task-focused; avoid redundant headings/help, nested cards, decorative AI motifs and extra confirmations. Keep notices next to the controls they explain.
- Reference the Tasty step-by-step pattern for focused instructions and short, optional, licensed media—not its brand styling.
- Production-ready and meticulously aligned: equivalent controls share dimensions, icon treatment, spacing and states across routes and breakpoints.

## Implementation defaults

- Use Angular standalone components, shared UI controls, project SCSS tokens and existing forms/i18n patterns. Keep validation in helpers and API requests in existing services; do not add dependencies for routine UI.

## Interaction defaults

- Use tabs/subtabs to keep editing, planning and cooking flows focused; do not stack every section into one long screen.
- Keep the global lateral navigation; avoid mobile bottom navigation.
- Provide keyboard/focus support, touch targets, reduced-motion and data-saving behavior. Media is optional and never blocks recipe content.
- AI output is a reviewable draft. Explicit user action applies it; explicit Save persists it.
